# GAME OVER? 홈페이지 관리자 매뉴얼

이 문서 하나면 홈페이지를 운영할 수 있습니다. **코드를 몰라도 됩니다.**

---

## 1. 홈페이지가 돌아가는 방식

```
구글 시트에서 내용 수정
        ↓
[사이트 업데이트] 실행
        ↓
GitHub 가 1~2분간 새 홈페이지를 만듦
        ↓
방문자에게 반영
```

**중요한 점 세 가지**

- **내 컴퓨터는 서버가 아닙니다.** 노트북을 꺼도 홈페이지는 계속 떠 있습니다.
- **시트를 고치는 것만으로는 반영되지 않습니다.** 아래 2번의 갱신 절차를 거쳐야 합니다.
- **잘못 적으면 배포가 멈추고 이유를 알려줍니다.** 이상한 내용이 홈페이지에 올라가는 일은 없습니다.

---

## 2. 홈페이지 갱신하기

시트를 고친 뒤, 아래 셋 중 하나만 하면 됩니다.

| 방법 | 하는 법 | 반영 시간 |
| --- | --- | --- |
| **시트 메뉴** (가장 편함) | 시트 상단 **GAME OVER? → 사이트 업데이트** | 1~2분 |
| **GitHub 버튼** | 저장소 → **Actions** 탭 → 왼쪽 `Deploy to GitHub Pages` → **Run workflow** | 1~2분 |
| **자동** | 아무것도 안 함 | 매일 오전 9시, 오후 9시 |

> **행사 당일에는 자동(하루 2회)을 믿지 마세요.** 타임테이블이 바뀌면 시트를 고친 뒤 반드시 메뉴를 눌러야 합니다.

### 갱신이 잘 됐는지 확인

저장소의 **Actions** 탭에 실행 목록이 보입니다.

- **초록 체크(✓)** — 성공. 홈페이지에 반영됐습니다.
- **빨간 엑스(✗)** — 실패. 항목을 클릭하고 `Build static site` 를 펼치면 이유가 한글로 나옵니다.

```
────────────────────────────────────────
시트를 읽지 못해 배포를 멈췄습니다.

시트 내용에 문제가 있습니다:
  · "인디"의 "세션 2"(14:35~15:10)와 "세션 3"(15:00~15:35)의 시간이 겹칩니다.

시트를 고친 뒤 Actions 탭에서 다시 실행해 주세요.
────────────────────────────────────────
```

**실패해도 기존 홈페이지는 그대로 살아 있습니다.**

## 3. 시트 탭 안내

탭은 8개입니다. 이름을 바꾸면 읽지 못하니 그대로 두세요.

| 탭 | 무엇을 적나 |
| --- | --- |
| **기본정보** | 행사 이름, 날짜, 장소, 신청 폼 주소 등 |
| **소개** | 행사 성격 설명, "이런 발표는 하지 않습니다" 목록 |
| **강연구성** | 모든 강연이 지나는 칸 (상황 · 다시 한다면). 사이는 연사가 채웁니다 |
| **트랙** | 발표 주제 (기업 / 인디). 트랙을 나누지 않으므로 표식으로만 쓰입니다 |
| **일정** | **타임테이블 · 연사 · 세션 상세가 전부 여기서 나옵니다** |
| **오시는길** | 장소, 주소, 교통 안내 |
| **연사안내** | `/speakers` 페이지 내용. 자료 마감과 템플릿 주소 |
| **FAQ** | 자주 묻는 질문 |

### 3-1. 일정 탭이 가장 중요합니다

연사 목록을 따로 관리하지 않습니다. 이 탭 한 곳만 고치면 타임테이블과 연사 정보가 함께 바뀝니다.

| 열 | 설명 |
| --- | --- |
| 시작 / 종료 | `13:45` 처럼 **시:분** 으로. 형식이 다르면 배포가 멈춥니다 |
| 구분 | `공통`, `휴식`, 또는 **트랙 탭에 적은 이름 그대로** (기업 / 인디) |
| 제목 | 세션 제목. 비우면 배포가 멈춥니다 |
| 연사 / 소속 | 확정 전에는 비워 두세요. 화면에 "연사 섭외 중"으로 나옵니다 |
| 장소 | 강의실이 확정되면 적으세요. 비워 두면 화면에 나오지 않습니다 |
| 주소이름 | 영문 소문자·숫자·하이픈. **적은 줄만 세션 상세 페이지가 생깁니다** |
| 요약 | 세션 소개 한두 문단 |
| 사진 | 연사 사진. `images/파일이름.png` 처럼 적고 파일은 `public/images/` 에 넣습니다 |

**시작 시각이 같은 줄은 화면에서 한 행에 나란히 놓입니다.**
지금은 트랙을 나누지 않아 한 시각에 한 줄만 섭니다. 나중에 같은 시각에 두 세션을 두면
그대로 나란히 표현됩니다.

**쉬는 시간도 한 줄로 적으세요.** 구분을 `휴식` 으로 하면 흐리게 표시되고 상세 페이지를 만들지 않습니다.

### 3-2. 자동으로 걸러지는 실수

배포 전에 아래를 검사합니다. 하나라도 걸리면 멈추고 어느 줄인지 알려줍니다.

- 시간이 `시:분` 형식이 아니거나, 종료가 시작보다 빠른 경우
- 구분에 트랙 탭에 없는 이름을 적은 경우
- **같은 트랙 안에서 두 세션의 시간이 겹치는 경우** — 손으로 적다 보면 실제로 자주 생깁니다
- 주소이름이 겹치거나, 영문 소문자·숫자·하이픈이 아닌 글자가 섞인 경우
- 휴식 줄에 주소이름을 적은 경우
- 신청 주소가 `http://` 또는 `https://` 로 시작하지 않는 경우

## 4. 자주 하는 작업

### 연사가 확정됐을 때

`일정` 탭에서 해당 줄의 **연사 · 소속 · 제목 · 요약** 을 채우고 갱신하면 됩니다.
타임테이블, 세션 상세 페이지가 한꺼번에 바뀝니다.

### 참가 신청을 열 때

1. 구글 폼을 만듭니다. (응답은 자동으로 시트에 쌓입니다)
2. `기본정보` 탭의 **신청 주소** 에 폼 주소를 붙여 넣습니다.
3. 갱신합니다. 헤더와 히어로의 버튼이 "참가 신청 준비 중" 에서 실제 링크로 바뀝니다.

주소를 비워 두면 버튼이 눌리지 않는 회색으로 보이므로, 준비되기 전에 열릴 걱정은 없습니다.

### 발표 자료 템플릿 링크를 걸 때

`연사안내` 탭의 **템플릿(다크) 주소 / 템플릿(라이트) 주소** 에 내려받기 주소를 넣습니다.
비워 두면 그 버튼이 "준비 중" 으로 보입니다. 연사 섭외 메일에는 `/speakers` 주소를 넣으면 됩니다.

### 장소가 확정됐을 때

`기본정보` 탭의 **장소**, `오시는길` 탭의 **장소명 · 주소 · 교통 안내 · 지도 주소**, 그리고 `일정` 탭 각 줄의 **장소** 를 고칩니다.

---

## 5. 사진 넣기

1. 사진 파일을 저장소 `public/images/` 에 올립니다. (GitHub 웹에서 **Add file → Upload files**)
2. 시트에는 `images/파일이름.png` 처럼 적습니다.

> 파일 이름은 **영문 소문자와 하이픈** 을 권합니다. 배포되는 곳은 대소문자를 가리므로 `Photo.PNG` 와 `photo.png` 가 다른 파일입니다. (배포 스크립트가 실제 파일 이름을 찾아 맞춰 주긴 하지만, 처음부터 맞추는 편이 안전합니다.)

없는 파일을 가리키면 그 자리만 비고 배포는 계속됩니다. Actions 로그에 경고가 남습니다.

## 6. 처음 한 번만 하는 설정

### 6-1. GitHub Pages 켜기

저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿉니다.

### 6-2. 시트 연결

1. 저장소에서 `sheet-template` 폴더의 CSV 8개를 내려받습니다.
2. 구글 시트를 새로 만들고, **CSV 파일 이름과 똑같은 이름의 탭**을 만들어 각각 가져옵니다.
   (파일 → 가져오기 → 업로드 → **현재 시트에 삽입**. 구분 문자는 쉼표)
3. 시트 **공유** 를 **"링크가 있는 모든 사용자 · 뷰어"** 로 바꿉니다. 이걸 안 하면 읽지 못합니다.
4. 시트 주소에서 ID 를 복사합니다.
   `https://docs.google.com/spreadsheets/d/`**`이 부분이 ID`**`/edit`
5. 저장소 **Settings → Secrets and variables → Actions → Variables** 탭 → **New repository variable**
   - Name: `SHEET_ID`
   - Value: 4번에서 복사한 값

### 6-3. 시트에 업데이트 버튼 달기 (선택)

시트에서 **확장 프로그램 → Apps Script** 를 열고 아래를 붙여 넣은 뒤 저장합니다.
시트를 새로고침하면 상단에 `GAME OVER?` 메뉴가 생깁니다.

**토큰은 코드에 적지 마세요.** Apps Script 편집기 왼쪽 **프로젝트 설정 → 스크립트 속성 → 속성 추가**
에서 이름 `GITHUB_TOKEN`, 값에 토큰을 넣습니다. 코드에 적어 두면 시트 편집 권한이 있는 사람이
스크립트를 열어 그대로 가져갈 수 있습니다.

토큰은 GitHub → Settings → Developer settings → **Fine-grained personal access token** 에서
이 저장소에 대해 **`Contents: Read and write`** 와 **`Actions: Read`** 두 권한으로 만듭니다.
(`Actions: Read` 는 「배포 상태 확인」에 쓰입니다. 없으면 그 항목만 403 이 납니다.)

```javascript
const OWNER = 'Game-Dev-Conference-GAMEOVER';
const REPO  = 'GAMEOVER_Homepage';

/* 탭 이름은 fetch-sheet.mjs 가 이 철자 그대로 찾는다. 하나라도 다르면 배포가 멈춘다. */
const TABS = ['기본정보', '소개', '강연구성', '트랙', '일정', '오시는길', '연사안내', 'FAQ'];

function onOpen() {
  SpreadsheetApp.getUi().createMenu('GAME OVER?')
    .addItem('시트 점검', 'checkSheet')
    .addItem('사이트 업데이트', 'updateSite')
    .addItem('배포 상태 확인', 'checkDeploy')
    .addToUi();
}

/* 토큰은 코드가 아니라 스크립트 속성에 둔다. */
function token_() {
  const t = PropertiesService.getScriptProperties().getProperty('GITHUB_TOKEN');
  if (!t) {
    throw new Error(
      '스크립트 속성에 GITHUB_TOKEN 이 없습니다.\n' +
      '프로젝트 설정 → 스크립트 속성에서 추가해 주세요.'
    );
  }
  return t.trim();
}

function api_(path, options) {
  const opts = options || {};
  opts.headers = {
    Authorization: 'Bearer ' + token_(),
    Accept: 'application/vnd.github+json',
  };
  opts.muteHttpExceptions = true;
  return UrlFetchApp.fetch('https://api.github.com/repos/' + OWNER + '/' + REPO + path, opts);
}

/*
 * 배포가 멈추는 흔한 원인을 시트에서 미리 본다.
 * 빌드를 돌리고 빨간 엑스를 보는 것보다, 보내기 전에 아는 편이 빠르다.
 */
function problems_() {
  const ss = SpreadsheetApp.getActive();
  const out = [];

  TABS.forEach(function (name) {
    if (!ss.getSheetByName(name)) out.push('"' + name + '" 탭이 없습니다.');
  });

  const kinds = ['공통', '휴식'];
  const tracks = ss.getSheetByName('트랙');
  if (tracks) {
    tracks.getDataRange().getDisplayValues().slice(1).forEach(function (r) {
      if (r[1]) kinds.push(String(r[1]).trim());
    });
  }

  const plan = ss.getSheetByName('일정');
  if (plan) {
    plan.getDataRange().getDisplayValues().slice(1).forEach(function (r, i) {
      if (!r.join('').trim()) return;          // 빈 줄은 건너뛴다
      const where = '일정 ' + (i + 2) + '행';
      [['시작', r[0]], ['종료', r[1]]].forEach(function (pair) {
        if (!/^\d{1,2}:\d{2}$/.test(String(pair[1]).trim())) {
          out.push(
            where + '의 ' + pair[0] + ' "' + pair[1] + '" 이 시:분 형식이 아닙니다. ' +
            '칸 서식을 「일반」이 아니라 「텍스트」로 두세요.'
          );
        }
      });
      if (!String(r[3]).trim()) out.push(where + '의 제목이 비어 있습니다.');
      if (kinds.indexOf(String(r[2]).trim()) < 0) {
        out.push(where + '의 구분 "' + r[2] + '" 을 쓸 수 없습니다. 쓸 수 있는 값: ' + kinds.join(', '));
      }
    });
  }
  return out;
}

function checkSheet() {
  const p = problems_();
  SpreadsheetApp.getUi().alert(
    p.length ? '고칠 곳 ' + p.length + '개\n\n· ' + p.join('\n· ')
             : '이상 없습니다. 「사이트 업데이트」를 누르셔도 됩니다.'
  );
}

function updateSite() {
  const ui = SpreadsheetApp.getUi();

  const p = problems_();
  if (p.length) {
    const go = ui.alert(
      '시트에 문제가 있습니다',
      '· ' + p.slice(0, 8).join('\n· ') + '\n\n이대로 보내면 배포가 멈출 수 있습니다. 그래도 보낼까요?',
      ui.ButtonSet.YES_NO
    );
    if (go !== ui.Button.YES) return;
  }

  const res = api_('/dispatches', {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify({ event_type: 'update-content' }),
  });

  const code = res.getResponseCode();
  if (code === 204) {
    ui.alert('업데이트를 시작했습니다.\n1~2분 뒤 「배포 상태 확인」을 눌러 결과를 보세요.');
    return;
  }

  // 숫자만 보여주면 원인을 알 수 없으므로, 무엇을 고쳐야 하는지 함께 띄운다.
  const hint = {
    401: '토큰이 잘못됐습니다. 스크립트 속성의 GITHUB_TOKEN 을 다시 확인하세요.',
    403: '토큰 권한이 부족합니다. Contents 를 Read and write 로 주세요.',
    404: '저장소를 찾을 수 없습니다. OWNER 와 REPO 철자를 확인하세요.',
  }[code] || '알 수 없는 오류입니다.';

  ui.alert('실패 (' + code + ')\n\n' + hint + '\n\nGitHub 응답:\n' + res.getContentText());
}

/*
 * 204 는 "요청을 보냈다"는 뜻일 뿐, 배포가 성공했다는 뜻이 아니다.
 * 시트를 고친 사람이 Actions 탭까지 들어가지 않아도 결과를 알 수 있게 한다.
 */
function checkDeploy() {
  const ui = SpreadsheetApp.getUi();
  const res = api_('/actions/runs?per_page=1');

  if (res.getResponseCode() === 403) {
    ui.alert('토큰에 Actions: Read 권한이 없습니다.\nGitHub 에서 토큰 권한을 늘려 주세요.');
    return;
  }
  if (res.getResponseCode() !== 200) {
    ui.alert('상태를 읽지 못했습니다 (' + res.getResponseCode() + ').');
    return;
  }

  const run = JSON.parse(res.getContentText()).workflow_runs[0];
  if (!run) { ui.alert('실행 기록이 없습니다.'); return; }

  let msg;
  if (run.status === 'queued') msg = '차례를 기다리는 중입니다.';
  else if (run.status === 'in_progress') msg = '빌드 중입니다. 조금 뒤 다시 눌러 보세요.';
  else if (run.conclusion === 'success') msg = '성공했습니다. 홈페이지에 반영됐습니다.';
  else if (run.conclusion === 'failure') msg = '실패했습니다. 아래 주소를 열어 이유를 확인하세요.';
  else msg = '상태: ' + run.conclusion;

  ui.alert(msg + '\n\n' + run.html_url);
}
```

> **토큰은 만료됩니다.** 만들 때 만료일을 적어 두고 인수인계 문서에 남겨 주세요.
> 만료되면 버튼만 동작하지 않고, Actions 탭의 수동 실행은 계속 됩니다.

## 7. 문제가 생겼을 때

| 증상 | 원인과 해결 |
| --- | --- |
| `시트를 읽을 권한이 없습니다` | 시트 공유가 비공개로 바뀌었습니다. 6-2의 3번 참고 |
| `탭을 찾을 수 없습니다` | 탭 이름이 바뀌었습니다. CSV 파일 이름과 똑같이 되돌리세요 |
| `머리글에 없는 열` | 첫 줄(머리글)을 지웠거나 고쳤습니다. `sheet-template` 의 같은 CSV 를 다시 가져오세요 |
| `시간이 겹칩니다` | 같은 트랙에 두 세션이 겹칩니다. 시작·종료를 확인하세요 |
| `구분 "..."을 알 수 없습니다` | 트랙 탭에 없는 이름을 적었습니다. 철자와 띄어쓰기를 맞추세요 |
| 시트 메뉴가 안 보임 | Apps Script 를 저장한 뒤 시트를 새로고침하세요 |
| 버튼 눌러도 401/403 | 토큰이 만료됐거나 권한이 부족합니다. 6-3 참고 |
| 사진이 안 보임 | 파일이 `public/images/` 에 있는지, 시트 경로의 철자가 맞는지 확인 |

배포 전에 미리 점검하고 싶다면 (개발 환경이 있는 경우):

```bash
SHEET_ID="시트주소" npm run sheet:check
```
